# duty-separation Specification (delta: duty-separation)

## ADDED Requirements

### Requirement: Правило несовместимости прав

Census ДОЛЖЕН (MUST) поддерживать правила несовместимости — наборы прав, не подлежащие
совмещению в составе одной роли. Правило ДОЛЖНО (MUST) нести устойчивый идентификатор,
описание риска, привязку к мерам внешних наборов требований и перечень примитивов,
пересечение по которым считается конфликтом. Человекочитаемые тексты правила ДОЛЖНЫ (MUST)
храниться в дереве локализации по конвенции, принятой для каталога.

#### Scenario: Роль совмещает несовместимые права
- **WHEN** роль объявляет два права, входящих в одно правило несовместимости, и их
  раскрытия пересекаются по конфликтному примитиву
- **THEN** фиксируется нарушение с указанием роли, обоих прав, общего примитива и меры

#### Scenario: Пересечение вне конфликтных примитивов
- **WHEN** раскрытия двух прав правила пересекаются только по примитивам, не отмеченным как
  конфликтные
- **THEN** нарушение не фиксируется

### Requirement: Проверка на раскрытых примитивах

Проверка несовместимости ДОЛЖНА (MUST) выполняться на раскрытых примитивах прав, а не на
их идентификаторах. Совмещение, достигнутое разными правами, приводящими к одному
конфликтному примитиву, ДОЛЖНО (MUST) обнаруживаться так же, как прямое совмещение прав,
названных в правиле.

#### Scenario: Обход через синоним
- **WHEN** роль вместо права, названного в правиле, объявляет другое право, раскрывающееся
  в тот же конфликтный примитив
- **THEN** нарушение фиксируется

#### Scenario: Общий примитив показан в находке
- **WHEN** нарушение зафиксировано
- **THEN** находка называет конкретный примитив, по которому возник конфликт

### Requirement: Кардинальное правило

Census ДОЛЖЕН (MUST) поддерживать правила вида «не более заданного числа ролей обладают
указанным правом», вычисляемые по эффективной декларации устройства. Такое правило НЕ
ДОЛЖНО (MUST NOT) представляться как ограничение по парку устройств.

#### Scenario: Превышение допустимого числа ролей
- **WHEN** эффективная декларация содержит больше ролей с указанным правом, чем допускает
  правило
- **THEN** фиксируется нарушение с перечислением этих ролей

### Requirement: Исключение только подписанным решением

Отключение правила или вывод конкретной роли из-под него ДОЛЖНЫ (MUST) требовать явного
подписанного решения с обоснованием и сроком действия. Ручной флаг оператора, снимающий
правило, НЕ ДОЛЖЕН (MUST NOT) предусматриваться. Признак административного назначения роли
НЕ ДОЛЖЕН (MUST NOT) давать автоматического освобождения от правил.

#### Scenario: Попытка обойти правило флагом
- **WHEN** оператор пытается применить декларацию с нарушением, указав флаг обхода
- **THEN** такого флага не существует, применение отклоняется

#### Scenario: Действующее подписанное исключение
- **WHEN** для роли действует подписанное исключение из правила с непросроченным сроком
- **THEN** нарушение не блокирует применение и отражается в отчёте как разрешённое

#### Scenario: Истёкшее исключение
- **WHEN** срок подписанного исключения истёк
- **THEN** нарушение вновь блокирует применение

### Requirement: Экспорт взаимоисключающих ролей

Census ДОЛЖЕН (MUST) предоставлять перечень ролей, объявленных взаимоисключающими, в виде
стабильного машиночитаемого контракта для внешнего потребителя. Census НЕ ДОЛЖЕН (MUST
NOT) требовать наличия такого потребителя и НЕ ДОЛЖЕН (MUST NOT) утверждать, что
несовместимость обеспечена на уровне субъектов, допущенных к ролям.

#### Scenario: Экспорт доступен
- **WHEN** декларация объявляет пары взаимоисключающих ролей
- **THEN** перечень доступен во внешнем контракте с указанием версии формата

#### Scenario: Граница обещания
- **WHEN** формируется отчёт о разделении обязанностей
- **THEN** он относится к составу ролей и явно не утверждает проверку допуска людей к ролям
