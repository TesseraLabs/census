# Tasks: duty-separation

Rust через `rust-pro`, срезами, TDD. На каждый срез: `cargo test` + `cargo clippy
--all-targets --all-features` зелёные, ревью `master-code-reviewer`. Коммит/PR — вне
рабочего окна (08:00–19:00 МСК). Зависит от `effect-classes`; исключения опираются на
механику подписанных отклонений (`baseline-profiles`) — до её готовности исключения не
реализуются, правило работает в режиме обнаружения.

## 1. Формат правил

- [ ] 1.1 Структура правила в каталоге: идентификатор, набор прав, перечень конфликтных
      примитивов, привязка к мерам, версия схемы; тексты — в дерево l10n.
- [ ] 1.2 Кардинальное правило: право + предельное число ролей.
- [ ] 1.3 Строгий разбор, отказ на неизвестных полях, forward-совместимость по конвенции
      каталога (неизвестный идентификатор права — форвард-ссылка, не ошибка).

## 2. Вычисление нарушений

- [ ] 2.1 Раскрытие прав роли в примитивы (переиспользовать существующий резолв, не
      дублировать).
- [ ] 2.2 Пересечение по конфликтным примитивам; находка несёт роль, оба права и общий
      примитив.
- [ ] 2.3 Тест обхода через синоним: право, не названное в правиле, но дающее тот же
      конфликтный примитив, — нарушение.
- [ ] 2.4 Тест отсутствия ложного срабатывания: пересечение по неконфликтному примитиву —
      не нарушение.
- [ ] 2.5 Кардинальные правила по эффективной декларации; тест, что счёт идёт по устройству.

## 3. Обнаружение и блокировка

- [ ] 3.1 Находки в `doctor` с устойчивыми идентификаторами и уровнями.
- [ ] 3.2 Гейт в `apply` до снапшота; перечисление всех нарушений.
- [ ] 3.3 Тест: система не изменена при отказе.

## 4. Исключения

- [ ] 4.1 Учёт подписанного исключения: правило целиком либо конкретная роль, срок,
      обоснование.
- [ ] 4.2 Истёкшее исключение вновь блокирует; тест на границе срока.
- [ ] 4.3 Отсутствие какого-либо флага обхода — тест, проверяющий, что CLI такого флага не
      имеет.
- [ ] 4.4 Административная роль без автоматической амнистии — тест.

## 5. Экспорт для auth-пути

- [ ] 5.1 Контракт перечня взаимоисключающих ролей: стабильный формат, версия схемы.
- [ ] 5.2 Отсутствие потребителя — не ошибка; экспорт самодостаточен.
- [ ] 5.3 Golden-тест контракта.

## 6. Наполнение и документация

- [ ] 6.1 Первичный набор правил по мерам: управление аудитом против чтения и очистки
      журналов, выдача прав против их согласования, эксплуатация против внесения изменений.
- [ ] 6.2 Раздел документации о границе: проверяется состав ролей, не допуск людей к ролям;
      формулировки наружу согласовать с правилами текстов Tessera.
- [ ] 6.3 Раздел о внедрении на парке с существующими нарушениями: сначала обнаружение,
      затем блокировка.
