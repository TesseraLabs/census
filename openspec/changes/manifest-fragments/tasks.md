# Tasks: manifest-fragments

Rust через `rust-pro`, срезами, TDD. На каждый срез: `cargo test` + `cargo clippy
--all-targets --all-features` зелёные, ревью `master-code-reviewer`. Коммит/PR — вне
рабочего окна (08:00–19:00 МСК). Зависит от `effect-classes` (скоупы в терминах классов):
раздел 2 не начинать до готовности шкалы.

Форматы делегации и фрагмента — публичные версионируемые контракты с первого релиза:
поле версии схемы вводится сразу, golden-тесты фиксируют формат.

## 1. Чтение и слияние (без доверия)

- [ ] 1.1 Модуль сбора фрагментов: обход `/usr/share/census/manifests.d/<line>/<name>.toml`,
      лимит размера до разбора, строгий парсер, стабильная сортировка по `line/name`.
- [ ] 1.2 Аддитивное слияние в эффективную декларацию; отказ при попытке override/negation.
- [ ] 1.3 Детекция конфликтов: один объект из двух источников → отказ с перечислением
      источников. Тест: конфликт фрагмент↔фрагмент и фрагмент↔операторская декларация.
- [ ] 1.4 Тест детерминизма: перемешанный порядок чтения → побайтово одинаковый результат.

## 2. Цепочка доверия

- [ ] 2.1 Формат делегации (`/etc/census/trust.d/<line>.toml`): линия, публичный ключ,
      скоуп (`max_effect_class`, домены, префикс имён), срок, `signature`; версия схемы.
- [ ] 2.2 Верификация делегации корнем по конвенции удаляемой строки `signature`
      (переиспользовать существующий код проверки, не дублировать).
- [ ] 2.3 Верификация фрагмента ключом своей линии; отказ при подписи чужой линией.
- [ ] 2.4 Применение скоупа: домены, класс, префикс. Дефолт без скоупа = только `curated`.
- [ ] 2.5 Тест независимости скоупа и политики оператора (нужны оба).
- [ ] 2.6 Отказ всей операции при любом невалидном фрагменте (тест: 10 валидных + 1 битый).

## 3. Анти-откат по фрагментам

- [ ] 3.1 Персист floor'ов `/var/lib/census/fragments.version`, ключ `line/name`, root-only.
- [ ] 3.2 Отказ при понижении версии; floor двигается только после успешного apply.
- [ ] 3.3 Тест сценария «удалили → вернули со старой версией» → отказ.
- [ ] 3.4 Операция оператора для чистки floor'ов (явная, аудируемая).

## 4. Происхождение и снятие

- [ ] 4.1 `src/state.rs`: источник объекта в managed-реестре; миграция реестров без поля
      (объект без источника = операторский).
- [ ] 4.2 План снятия объектов исчезнувшего источника; подпись не требуется.
- [ ] 4.3 Anti-lockout при снятии (тест: снятие последнего пути доступа отклоняется).
- [ ] 4.4 `census plan`: вклад по источникам в человекочитаемом выводе и в JSON.

## 5. Интеграция с доверием декларации

- [ ] 5.2 Режим `--trust-fs` распространяется на фрагменты, факт фиксируется в журнале.

## 6. Упаковка и документация
