## Why

Сегодня софт настраивает доступ maintainer-скриптами и drop-in каталогами (`sudoers.d` и
подобными): изменения невидимы для плана, не имеют подписи автора и остаются на машине
после удаления пакета, если скрипт забыл убрать за собой. Цель — чтобы пакет **объявлял**
нужные ему объекты доступа фрагментом декларации Census, а не применял их скриптом:
фрагмент подписан издателем, проверяется до применения, виден в плане с указанием
источника и автоматически снимается при исчезновении (удалении пакета).

## What Changes

- Новый слой источников декларации: каталог фрагментов `/usr/share/census/manifests.d/`
  (vendor-слой; deb/rpm-пакеты кладут сюда файлы и **ничего не применяют** — применение
  остаётся отдельной фазой `census apply`).
- Цепочка доверия фрагментов, проверяемая самим Census (самостоятельность без внешнего
  координатора): пинённый корень (`/etc/census/trust.pub`, уже существующий) подписывает
  **делегации линий** в `/etc/census/trust.d/<line>.toml` — публичный ключ линии плюс её
  скоуп; фрагмент подписан ключом своей линии. Скоуп делегации задаётся в терминах
  классов эффектов (`effect-classes`) и допустимых доменов; дефолт скоупа — только
  `curated`.
- Анти-откат по-фрагментно: монотонная версия каждого фрагмента, персист по идентификатору
  `line/name` в `/var/lib/census/`.
- Слияние в эффективную декларацию: операторская декларация + прошедшие проверку
  фрагменты. Фрагменты **только добавляют** объекты (никаких override/negation);
  объявление одного объекта двумя источниками — fail-closed отказ с перечислением
  источников. Итог слияния детерминирован и не зависит от порядка чтения.
- Происхождение: managed-реестр хранит источник каждого объекта; `census plan` показывает
  вклад по источникам. Исчезновение фрагмента порождает план снятия его объектов —
  подписи не требует (снятие только сужает права).

## Capabilities

### New Capabilities
- `fragment-trust`: делегации линий (формат, подпись корнем, скоуп), верификация подписи
  фрагмента, по-фрагментный anti-rollback, fail-closed на каждом шаге цепочки.
- `manifest-fragments`: раскладка каталога фрагментов, формат фрагмента, детерминированное
  слияние с fail-closed конфликтами, происхождение объектов и снятие при исчезновении
  источника.

### Modified Capabilities
- `declaration-trust`: доверие расширяется с единственной декларации до множества
  источников (операторская декларация — как раньше; фрагменты — по цепочке
  `fragment-trust`); anti-rollback-персист становится множественным.
- `provisioning-apply`: managed-реестр записывает источник объекта; снятие объектов
  исчезнувшего источника проходит обычным планом (снапшот, отчёт).

## Impact

- Код: новый модуль сбора/слияния фрагментов; `src/trust.rs` (делегации, по-фрагментный
  персист версий); `src/state.rs` (источник в managed-реестре); `src/plan.rs` (вклад по
  источникам, конфликты).
- Контракты: формат фрагмента и делегации — новый публичный версионируемый контракт
  (schema-поле с первого дня, дисциплина как у интерфейс-контракта CLI/TOML).
- Упаковка: конвенция для пакетов, кладущих фрагменты (пути, имена, запрет применения из
  maintainer-скриптов) — документируется, связка с change `package-deb-rpm` (раскладка
  `/usr/share/census/` уже там).
- Зависит от change `effect-classes` (скоупы делегаций в терминах классов).
