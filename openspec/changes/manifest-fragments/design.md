## Context

Пакетный софт настраивает доступ maintainer-скриптами и drop-in каталогами: невидимо для
плана, без подписи автора полезной нагрузки, с мусором после удаления пакета. Целевая
модель линейки: пакет **объявляет** объекты фрагментом декларации Census; применение —
отдельная фаза вне dpkg-транзакции. Решение владельца (2026-08-20): каждый фрагмент
подписан, цепочку проверяет сам Census — самостоятельность без внешнего координатора.
У Census уже есть: пинённый корень `/etc/census/trust.pub`, Ed25519-подпись декларации с
удаляемой строкой `signature`, монотонный anti-rollback, строгий парсинг, managed-реестр.

## Goals / Non-Goals

**Goals:**
- Фрагменты декларации из пакетов: подписаны издателем, проверены до применения, видимы
  в плане с источником, сняты при исчезновении.
- Цепочка доверия внутри Census: корень → делегация линии (скоуп) → фрагмент.
- Детерминированное слияние с fail-closed конфликтами.

**Non-Goals:**
- Не делаем полный owner-rooted trust апдейтера (security epoch, отзыв через бандлы,
  контрподпись) — у Census минимально достаточная цепочка; расширение до общей
  библиотеки — только при втором реальном потребителе.
- Не оркеструем установку пакетов и порядок фаз системы — это апдейтер.
- Не даём фрагментам PAM-объекты и объекты вне допущенных доменов.
- Maintainer-скрипты, вызывающие `census apply`, — анти-паттерн, документируется как
  запрещённый (enforce внутри dpkg невозможен).

## Decisions

### D1. Раскладка: vendor-слой отделён от операторского

Фрагменты пакетов — `/usr/share/census/manifests.d/<line>/<name>.toml` (владение —
пакеты, root-only запись); операторская декларация `/etc/census/declaration.toml` — как
сегодня. Альтернатива «фрагменты в /etc» отвергнута: /usr/share — принадлежащее пакетам
и попадающее под dpkg-инвентарь место; /etc — операторское.

### D2. Делегации линий в `/etc/census/trust.d/`

Делегация — TOML-файл: `line`, публичный ключ линии, скоуп (`max_effect_class`,
допустимые домены, опциональный префикс имён объектов), срок действия (опционально),
`signature` корнем (та же конвенция удаляемой строки). Ключ линии ≠ корень; корень
делегирует и может отозвать удалением файла делегации (root-only /etc). Альтернатива
«фрагменты подписаны прямо корнем» отвергнута: один ключ на всех издателей — общий blast
radius и невозможность per-line скоупа.

### D3. Скоуп по умолчанию — `curated`

Делегация без явного скоупа разрешает только curated-объекты допущенных доменов.
`escalation` во фрагменте требует и явного скоупа делегации, и политики оператора,
допускающей класс (`effect-classes`); оба условия независимы и fail-closed.

### D4. Анти-откат по-фрагментно, идентичность — `line/name`

Каждый фрагмент несёт `version` (монотонный u64); персист floor'ов — единый TOML
`/var/lib/census/fragments.version` с ключами `line/name`. Понижение версии — отказ
фрагмента (и всего apply — см. D6). Исчезновение фрагмента floor не трогает: возврат
пакета со старой версией фрагмента после удаления — отказ (защита от отката через
удаление/установку). Floor чистится только явной операцией оператора.

### D5. Слияние аддитивно, конфликты fail-closed, детерминизм

Фрагменты только добавляют объекты. Один объект (группа, роль, sysctl-ключ, юнит…) из
двух источников — конфликт: отказ с перечислением источников; разрешение — только
изменением самих источников (или явным будущим механизмом приоритета — вне scope).
Результат слияния не зависит от порядка чтения каталога (сортировка по `line/name`).
Альтернатива «последний выигрывает» отвергнута: состояние машины начинает зависеть от
порядка установки пакетов — теряется воспроизводимость.

### D6. Один невалидный фрагмент — отказ всего apply

Невалидный (подпись/скоуп/схема/anti-rollback) фрагмент не «пропускается с warning», а
валит apply целиком. Альтернатива «применить валидные, отложить битый» отвергнута:
частично применённая эффективная декларация — неопределённое состояние; поставщик битого
фрагмента должен чинить пакет, а не жить в тени.

### D7. Снятие при исчезновении — без подписи

Объекты managed-реестра, чей источник (`line/name`) исчез из каталога фрагментов,
попадают в план снятия. Подпись не требуется: снятие только сужает права (аддитивная
модель D5 гарантирует, что фрагменты не несут deny-семантики, чьё снятие расширяло бы
доступ). Анти-lockout действует и здесь.

## Risks / Trade-offs

- **Дублирование доверия с апдейтером.** Осознанная цена самостоятельности Census;
  механика намеренно минимальна (делегация-файл + подпись фрагмента). Извлечение общего
  крейта — при втором потребителе.
- **Ротация ключа линии** = новая делегация тем же именем линии (подпись корнем);
  одновременное сосуществование двух ключей одной линии не поддерживается в v1 —
  упрощение, зафиксировать в доке.
- **Персист floor'ов растёт** с числом когда-либо виденных фрагментов; чистка — ручная
  операция оператора. Приемлемо: единицы-десятки записей.
- **/usr/share как источник объявлений** доверен не потому, что путь особенный, а потому
  что каждый файл проверяется подписью; путь лишь конвенция раскладки.
