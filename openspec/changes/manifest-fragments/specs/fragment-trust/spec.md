# fragment-trust Specification (delta: manifest-fragments)

## ADDED Requirements

### Requirement: Делегация линии, подписанная корнем

Census ДОЛЖЕН (MUST) принимать фрагменты декларации только от линий, для которых в
root-only каталоге `/etc/census/trust.d/` лежит делегация, подписанная пинённым корнем
(`/etc/census/trust.pub`) по той же конвенции, что и декларация (подпись покрывает байты с
полностью удалённой строкой `signature`). Делегация ДОЛЖНА (MUST) содержать имя линии,
публичный ключ линии и скоуп. Делегация с невалидной подписью, неизвестными полями или
истёкшим сроком ДОЛЖНА (MUST) отвергаться, а фрагменты её линии — не приниматься
(fail-closed).

#### Scenario: Валидная делегация
- **WHEN** в `/etc/census/trust.d/` лежит делегация линии, подписанная корнем
- **THEN** фрагменты этой линии допускаются к проверке подписи ключом линии

#### Scenario: Делегация подделана
- **WHEN** подпись делегации не сходится с пинённым корнем
- **THEN** делегация отвергается, ни один фрагмент этой линии не принимается

#### Scenario: Отзыв удалением
- **WHEN** файл делегации линии удалён из `/etc/census/trust.d/`
- **THEN** фрагменты этой линии перестают приниматься, а их объекты попадают в план снятия

### Requirement: Скоуп делегации

Делегация ДОЛЖНА (MUST) задавать скоуп линии: максимальный класс эффекта, перечень
допустимых доменов и, опционально, префикс имён объектов. Отсутствие явного скоупа ДОЛЖНО
(MUST) означать наиболее узкий скоуп: только класс `curated`. Фрагмент, объявляющий объект
вне скоупа своей линии, ДОЛЖЕН (MUST) отвергаться до применения.

#### Scenario: Скоуп по умолчанию
- **WHEN** делегация не задаёт скоуп явно, а фрагмент объявляет объект класса `raw`
- **THEN** фрагмент отвергается

#### Scenario: Объект вне допустимого домена
- **WHEN** скоуп линии допускает домен sysctl, а фрагмент объявляет объект доступа
- **THEN** фрагмент отвергается с указанием линии, объекта и нарушенного ограничения

#### Scenario: Скоуп и политика независимы
- **WHEN** скоуп линии допускает `escalation`, а политика оператора ограничивает `raw`
- **THEN** объект отвергается политикой; выполнение обоих условий обязательно

### Requirement: Подпись фрагмента ключом линии

Каждый фрагмент ДОЛЖЕН (MUST) нести подпись, проверяемую публичным ключом своей линии из
делегации, по конвенции удаляемой строки `signature`. Фрагмент без подписи, с невалидной
подписью или подписанный ключом другой линии ДОЛЖЕН (MUST) отвергаться до любых мутаций.

#### Scenario: Фрагмент без подписи
- **WHEN** в каталоге фрагментов лежит файл без строки `signature`
- **THEN** он отвергается, apply не выполняет мутаций

#### Scenario: Подпись чужой линией
- **WHEN** фрагмент линии A подписан ключом линии B
- **THEN** он отвергается

### Requirement: Анти-откат по фрагментам

Каждый фрагмент ДОЛЖЕН (MUST) нести монотонную версию. Census ДОЛЖЕН (MUST) персистить
последнюю успешно применённую версию каждого фрагмента по идентификатору `линия/имя` в
root-only хранилище и отвергать фрагмент с меньшей версией. Исчезновение фрагмента НЕ
ДОЛЖНО (MUST NOT) сбрасывать персист: возврат фрагмента со старой версией после удаления
ДОЛЖЕН (MUST) отвергаться. Персист ДОЛЖЕН (MUST) обновляться только после успешного apply.

#### Scenario: Понижение версии фрагмента
- **WHEN** фрагмент приходит с версией меньше персиста
- **THEN** он отвергается, мутаций нет

#### Scenario: Откат через удаление и возврат
- **WHEN** фрагмент удалён, затем возвращён с версией ниже ранее применённой
- **THEN** он отвергается

#### Scenario: Персист двигается после успеха
- **WHEN** apply с новой версией фрагмента откатывается из-за сбоя
- **THEN** персист версии этого фрагмента не изменяется
