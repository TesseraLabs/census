# exposure-audit Specification (delta: exposure-mac-provider)

## MODIFIED Requirements

### Requirement: Честность DAC-only вердикта

Аудит ДОЛЖЕН (MUST) вычислять дискреционный доступ (DAC: режим, владелец, группы, POSIX ACL)
независимо и НЕ ДОЛЖЕН (MUST NOT) кодировать в open-ядре ни одного мандатного правила (Biba/BLP/
type-enforcement). Уточнение вердикта мандатным контролем ДОЛЖНО (MUST) идти ТОЛЬКО через SPI
`MacProvider`. Когда активен `NullMacProvider` (дефолт open-билда) ИЛИ провайдер не вернул метку,
вердикт остаётся DAC, и вывод ДОЛЖЕН (MUST) документировать, что это верхняя граница (MAC может
ограничить сильнее). Когда активен реальный провайдер, вердикт есть DAC ∧ MAC, и вывод ДОЛЖЕН
(MUST) указывать учтённую MAC-систему (`DAC + <system>`), а НЕ прежнюю DAC-only пометку.

#### Scenario: Нет провайдера — DAC-only верхняя граница
- **WHEN** активен `NullMacProvider` (open-билд по умолчанию)
- **THEN** вывод несёт пометку DAC-only верхней границы, а находки идентичны чисто-DAC результату

#### Scenario: Активен провайдер — DAC + MAC
- **WHEN** инжектнут реальный `MacProvider` (напр. system=parsec)
- **THEN** вывод указывает `DAC + parsec`, а вердикт учитывает мандатные ограничения через SPI

### Requirement: Вывод, стабильный контракт и неутечка секретов

Аудит ДОЛЖЕН (MUST) поддерживать `--format text|json`; JSON ДОЛЖЕН (MUST) быть стабильным
контрактом, зафиксированным golden-тестами (schemars/clap, как у прочих команд). Схема находки
ДОЛЖНА (MUST) включать поле `mac` (nullable): при активном провайдере оно несёт учтённую систему и
контексты достижимости, при `NullMacProvider`/не-labeled объекте — `null`. Вывод НЕ ДОЛЖЕН (MUST
NOT) включать СОДЕРЖИМОЕ файлов класса secret и НЕ ДОЛЖЕН (MUST NOT) раскрывать содержимое мандатной
метки сверх её рендера (`render_label`) — только путь, режим и метаданные находки, так как сам отчёт
является чувствительным артефактом.

#### Scenario: JSON-контракт с полем mac
- **WHEN** аудит запущен с `--format json`
- **THEN** вывод соответствует golden-схеме, каждая находка несёт поле `mac` (объект или `null`)

#### Scenario: Секрет не раскрывается
- **WHEN** находка касается объекта класса secret
- **THEN** в выводе есть путь и режим, но НЕ содержимое файла

## ADDED Requirements

### Requirement: MAC-нейтральный SPI MacProvider

Open-ядро ДОЛЖНО (MUST) определять SPI `MacProvider` с методами `system()` (`Parsec`|`Selinux`|…),
`object_label(path) -> Option<MacLabelId>`, `principal_contexts(uid) -> Vec<MacContextId>`,
`permits(ctx, label, access) -> bool`, `render_context`/`render_label`. `MacLabelId` и `MacContextId`
ДОЛЖНЫ (MUST) быть непрозрачными для ядра (интернированные хэндлы); ядро НЕ ДОЛЖНО (MUST NOT) парсить
метку, предполагать решётку или порядок контекстов, либо кодировать мандатное правило — вся
мандатная семантика ДОЛЖНА (MUST) находиться за `permits` в бэкенде. `principal_contexts` ДОЛЖЕН
(MUST) возвращать НЕУПОРЯДОЧЕННОЕ множество (чтобы SELinux type-enforcement без порядка ложился в тот
же SPI, что и решётка PARSEC).

#### Scenario: Ядро не интерпретирует метки
- **WHEN** ядро получает `MacLabelId`/`MacContextId` от провайдера
- **THEN** оно передаёт их обратно в `permits`/`render_*` не разбирая, без предположений о порядке

#### Scenario: Дефолт NullMacProvider нейтрален
- **WHEN** активен `NullMacProvider`
- **THEN** `object_label` даёт `None`, `permits` даёт `true`, поведение аудита не меняется

### Requirement: Композит DAC ∧ MAC с перечислением контекстов

Композиция ДОЛЖНА (MUST) выполняться ПОВЕРХ существующего DAC-вычисления (`effective()` остаётся
чисто-DAC и НЕ ДОЛЖНА (MUST NOT) изменяться). Для находки на объекте БЕЗ метки (`object_label` даёт
`None`) аудит ДОЛЖЕН (MUST) сохранить находку без аннотации (`mac = null`) — MAC-данных для сужения
нет. Для находки на labeled-объекте аудит ДОЛЖЕН (MUST) вычислить принимаемые контексты принципала
`principal_contexts(uid)` и отфильтровать их `permits(ctx, object_label(path), access)`. Подавление
ДОЛЖНО (MUST) происходить ТОЛЬКО когда множество принимаемых контекстов НЕПУСТО, но `permits` не даёт
доступ НИ В ОДНОМ из них (доказанно недостижимо во всех контекстах). Если провайдер НЕ вернул
контекстов для принципала (пустой `principal_contexts`), находка ДОЛЖНА (MUST) быть СОХРАНЕНА без
аннотации (`mac = null`) — отсутствие контекстов есть отсутствие MAC-данных, а НЕ доказательство
недостижимости; подавлять её было бы fail-open ложным отрицанием. Иначе (доступ разрешён хотя бы в
одном контексте) находка ДОЛЖНА (MUST) сохраниться с аннотацией `mac.reachable_in` (рендер этих
контекстов).

#### Scenario: MAC блокирует во всех контекстах — подавление
- **WHEN** у принципала есть контексты, но `permits` ложно к метке объекта в КАЖДОМ из них
- **THEN** DAC-находка подавляется и в вывод не попадает

#### Scenario: У принципала нет контекстов — находка сохраняется
- **WHEN** объект labeled, но `principal_contexts(uid)` пуст (провайдер не имеет данных о принципале)
- **THEN** находка сохраняется без аннотации (`mac = null`), НЕ подавляется

#### Scenario: Доступ есть в части контекстов — аннотация
- **WHEN** `permits` истинно в контексте Y, но ложно в X
- **THEN** находка сохраняется с `mac.reachable_in = [render_context(Y)]`

### Requirement: Аннотация меток в posture-режиме

В режиме `audit fs` (principal-independent) провайдер ДОЛЖЕН (MUST) только АННОТИРОВАТЬ каждый
объект его меткой (через `object_label`/`render_label`) и НЕ ДОЛЖЕН (MUST NOT) подавлять находки —
принципала для permit-проверки нет.

#### Scenario: Posture с метками
- **WHEN** `audit fs` при активном провайдере встречает labeled-объект
- **THEN** находка несёт рендер метки объекта, без подавления

### Requirement: Гейтинг включения MAC

Флаг `--mac` ДОЛЖЕН (MUST) в open-билде (нет слинкованного реального провайдера) завершаться честным
отказом («no MAC backend in this build»), а НЕ тихо работать как no-op. На хосте без запрошенной
MAC-системы провайдер ДОЛЖЕН (MUST) оставаться no-op, а вывод — сохранять DAC-only пометку.

#### Scenario: --mac в open-билде
- **WHEN** `--mac` задан, но реальный провайдер не слинкован
- **THEN** аудит отказывает с сообщением «no MAC backend in this build», ненулевой код

#### Scenario: MAC недоступен на хосте
- **WHEN** провайдер слинкован, но хост не несёт запрошенной MAC-системы
- **THEN** провайдер работает как no-op, вывод сохраняет DAC-only пометку
