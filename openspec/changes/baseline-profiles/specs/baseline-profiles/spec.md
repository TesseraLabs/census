# baseline-profiles Specification (delta: baseline-profiles)

## ADDED Requirements

### Requirement: Базлайн как подписанный версионированный объект

Census ДОЛЖЕН (MUST) поддерживать базлайн-профиль — именованный набор контролей, правил и
объектов с версией и подписью. Базлайн ДОЛЖЕН (MUST) проверяться по подписи до
использования; базлайн с невалидной подписью или неизвестным издателем НЕ ДОЛЖЕН (MUST
NOT) применяться.

#### Scenario: Импорт базлайна по имени и версии
- **WHEN** декларация ссылается на базлайн с указанием имени и версии
- **THEN** его состав входит в эффективную декларацию после проверки подписи

#### Scenario: Подделанный базлайн
- **WHEN** подпись базлайна не сходится
- **THEN** применение отклоняется до мутаций

### Requirement: Запрет локального редактирования базлайна

Импортированный базлайн НЕ ДОЛЖЕН (MUST NOT) изменяться декларацией устройства.
Специфичное для устройства ДОЛЖНО (MUST) добавляться декларацией отдельно и проходить
обычные гейты. Попытка переопределить элемент базлайна ДОЛЖНА (MUST) отвергаться.

#### Scenario: Попытка переопределить контроль базлайна
- **WHEN** декларация переопределяет параметр контроля, входящего в базлайн
- **THEN** разбор отвергает декларацию

### Requirement: Отчёт состояния соответствия

Census ДОЛЖЕН (MUST) сообщать состояние соответствия базлайну в трёх значениях:
соответствует, соответствует с действующими отклонениями, не соответствует. Отчёт ДОЛЖЕН
(MUST) перечислять причины несоответствия и действующие отклонения с их сроками.

#### Scenario: Соответствие с отклонениями
- **WHEN** все требования базлайна выполнены, кроме снятых действующими отклонениями
- **THEN** состояние — «соответствует с отклонениями», перечислены отклонения и сроки

#### Scenario: Несоответствие
- **WHEN** требование базлайна не выполнено и не снято отклонением
- **THEN** состояние — «не соответствует», причина названа
