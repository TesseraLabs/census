# Tasks: baseline-profiles

Rust через `rust-pro`, срезами, TDD; ревью `master-code-reviewer`; коммит/PR вне рабочего
окна. Зависит от `effect-classes`, `enumerable-domains`, `duty-separation`. Является
предпосылкой полноценных исключений в них — до этого change'а правила работают только в
режиме обнаружения.

## 1. Базлайн

- [ ] 1.1 Формат: имя, версия, состав (контроли, правила, объекты), издатель, подпись,
      версия схемы.
- [ ] 1.2 Проверка подписи базлайна отдельным полномочием (ключ издателя стандарта ≠ ключ
      разрешающего отклонения).
- [ ] 1.3 Импорт по ссылке из декларации; слияние с устройством-специфичным.
- [ ] 1.4 Запрет локального переопределения элементов базлайна; тест.

## 2. Отклонения

- [ ] 2.1 Формат: предмет, обоснование, область, срок, подпись.
- [ ] 2.2 Проверка применимости к устройству; умолчание — узкая область; чужое отклонение
      игнорируется.
- [ ] 2.3 Отказ при отсутствии срока; отказ целиком при попытке расширения.
- [ ] 2.4 Истечение возвращает требование в силу; тест на границе срока (без зависимости от
      доверенного времени — фиксировать источник времени и его ограничения явно).

## 3. Интеграция с гейтами

- [ ] 3.1 Учёт отклонений в гейте классов эффектов.
- [ ] 3.2 Учёт отклонений в гейте разделения обязанностей.
- [ ] 3.3 Тест: отклонение не отменяет защиту от lockout.

## 4. Отчёт соответствия

- [ ] 4.1 Три состояния, причины несоответствия, перечень действующих отклонений со сроками.
- [ ] 4.2 Число и сроки отклонений на виду (противовес злоупотреблению).
- [ ] 4.3 Различение «не соответствует редакции» и «не перешёл на новую редакцию».
- [ ] 4.4 JSON-контракт отчёта, golden-тест.

## 5. Данные и документация

- [ ] 5.1 Пример базлайна по изученному банковскому стандарту.
- [ ] 5.2 Раздел о разделении полномочий: издание стандарта и разрешение отступления —
      разные ключи.
- [ ] 5.3 Раздел об источнике времени: на офлайн-устройстве срок проверяется по локальному
      времени, ограничение зафиксировать честно.
