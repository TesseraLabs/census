# security-controls Specification (delta: enumerable-domains)

## ADDED Requirements

### Requirement: Каталог контролей безопасности

Census ДОЛЖЕН (MUST) поддерживать курируемый каталог контролей безопасности. Контроль
ДОЛЖЕН (MUST) нести устойчивый идентификатор, описание защищаемого риска, привязку к мерам
внешних наборов требований и раскрытие в конечный набор объектов доменов. Человекочитаемые
тексты контроля ДОЛЖНЫ (MUST) храниться в дереве локализации, а не в структурном файле
каталога, по конвенции, уже принятой для каталога разрешений и наборов требований.

#### Scenario: Контроль раскрывается в объекты
- **WHEN** декларация объявляет контроль из каталога
- **THEN** резолв раскрывает его в конечный набор объектов доменов, и они попадают в план

#### Scenario: Тексты в дереве локализации
- **WHEN** каталог контролей загружается
- **THEN** структурный файл не содержит человекочитаемых названий и описаний

### Requirement: Объявление контролей в декларации

Декларация ДОЛЖНА (MUST) позволять объявлять контроли по идентификаторам. Объявление
контроля НЕ ДОЛЖНО (MUST NOT) требовать перечисления его технических объектов. Неизвестный
идентификатор контроля ДОЛЖЕН (MUST) приводить к отказу разбора, а не к молчаливому
пропуску.

#### Scenario: Декларация в терминах контролей
- **WHEN** декларация перечисляет идентификаторы контролей и не перечисляет ключей
- **THEN** план содержит все объекты, в которые эти контроли раскрываются

#### Scenario: Неизвестный контроль
- **WHEN** декларация ссылается на отсутствующий в каталоге контроль
- **THEN** разбор отвергает декларацию с указанием идентификатора

### Requirement: Сырой объект как помеченный escape hatch

Прямое объявление объекта домена в обход каталога контролей ДОЛЖНО (MUST) оставаться
возможным и ДОЛЖНО (MUST) получать класс эффекта не ниже `raw`. Такое объявление ДОЛЖНО
(MUST) быть видимым в отчёте как некурируемое.

#### Scenario: Прямое объявление ключа
- **WHEN** декларация объявляет ключ домена напрямую, минуя контроли
- **THEN** объект применяется, помечен как некурируемый и имеет класс не ниже `raw`

### Requirement: Отчёт о состоянии контролей

Census ДОЛЖЕН (MUST) сообщать состояние каждого объявленного контроля: выполнен полностью,
выполнен частично либо не выполнен, с перечислением объектов, определивших вердикт. Отчёт
ДОЛЖЕН (MUST) отличать материализованное состояние от проверенного и НЕ ДОЛЖЕН (MUST NOT)
представлять применение объектов контроля как подтверждение выполнения внешнего
требования, которое проверяется, а не материализуется.

#### Scenario: Контроль выполнен частично
- **WHEN** часть объектов контроля применена, часть требует перезагрузки
- **THEN** контроль отражён как выполненный частично с перечислением незавершённых объектов

#### Scenario: Разделение применённого и проверенного
- **WHEN** контроль включает как материализуемые объекты, так и проверки
- **THEN** отчёт разделяет их и не выдаёт применение за прохождение проверки
