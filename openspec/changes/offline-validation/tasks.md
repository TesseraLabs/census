# Tasks: offline-validation

Rust через `rust-pro`, срезами, TDD; ревью `master-code-reviewer`; коммит/PR вне рабочего
окна. Зависит от `effect-classes`, `enumerable-domains`, `duty-separation`.

## 1. Режим

- [ ] 1.1 Точка входа без чтения живой системы и без требования root.
- [ ] 1.2 Разбор, слияние источников, резолв — переиспользование существующего кода.
- [ ] 1.3 Тест: работа от обычного пользователя на машине без целевой системы.

## 2. Гейты

- [ ] 2.1 Каждый гейт объявляет применимость без системы (признак в общей абстракции гейта).
- [ ] 2.2 Выполнение применимых гейтов; тот же код, что при применении.
- [ ] 2.3 Тест: новый гейт без объявленной применимости не компилируется либо падает тестом
      (защита от забытого гейта).

## 3. Вывод

- [ ] 3.1 Раздел выполненных и раздел невыполнимых проверок; непроверенное не опускается.
- [ ] 3.2 Коды возврата для трёх исходов; документировать.
- [ ] 3.3 Машиночитаемый отчёт, golden-тест.

## 4. Описание целевой системы

- [ ] 4.1 Необязательный вход: набор целей, модель, версия.
- [ ] 4.2 Дополнительные проверки применимости при его наличии.
- [ ] 4.3 Отсутствие входа — не ошибка; тест.

## 5. Эксплуатация

- [ ] 5.1 Пример шага конвейера в `examples/`.
- [ ] 5.2 Раздел документации: зелёный результат не является гарантией успешного применения;
      перечислить, что остаётся за пределами.
