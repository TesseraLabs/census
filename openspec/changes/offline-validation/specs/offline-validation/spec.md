# offline-validation Specification (delta: offline-validation)

## ADDED Requirements

### Requirement: Проверка декларации без живой системы

Census ДОЛЖЕН (MUST) предоставлять режим проверки декларации, не требующий чтения
фактического состояния системы и не требующий привилегий суперпользователя. Режим ДОЛЖЕН
(MUST) выполнять разбор, слияние источников, резолв и все гейты, применимые без системы.

#### Scenario: Проверка в конвейере
- **WHEN** режим запущен от обычного пользователя на машине без целевой системы
- **THEN** проверка выполняется, результат возвращается кодом возврата и отчётом

#### Scenario: Нарушение обнаружено без системы
- **WHEN** декларация содержит конфликт источников либо нарушение правила несовместимости
- **THEN** режим сообщает о нарушении, как это сделал бы гейт при применении

### Requirement: Перечень невыполнимых проверок

Вывод режима ДОЛЖЕН (MUST) содержать перечень проверок, невыполнимых без живой системы.
Такие проверки НЕ ДОЛЖНЫ (MUST NOT) пропускаться молча и НЕ ДОЛЖНЫ (MUST NOT) считаться
пройденными.

#### Scenario: Непроверенное названо
- **WHEN** проверка завершена без ошибок
- **THEN** вывод содержит раздел с перечнем того, что не проверялось без системы

### Requirement: Описание целевой системы как необязательный вход

Режим ДОЛЖЕН (MUST) принимать необязательное описание целевой системы и при его наличии
выполнять дополнительные проверки применимости. Отсутствие описания НЕ ДОЛЖНО (MUST NOT)
быть ошибкой.

#### Scenario: Без описания системы
- **WHEN** описание целевой системы не подано
- **THEN** проверка выполняется, а зависящие от него проверки попадают в непроверенные

### Requirement: Коды возврата для конвейера

Режим ДОЛЖЕН (MUST) различать кодами возврата исходы: декларация невалидна; валидна при
наличии невыполнимых проверок; валидна полностью. Разбор текстового вывода для определения
исхода НЕ ДОЛЖЕН (MUST NOT) требоваться.

#### Scenario: Различение исходов
- **WHEN** конвейер запускает проверку
- **THEN** исход определяется кодом возврата без разбора текста

### Requirement: Единство гейтов

Режим ДОЛЖЕН (MUST) использовать те же реализации гейтов, что и применение. Отдельная
облегчённая реализация проверок НЕ ДОПУСКАЕТСЯ (MUST NOT).

#### Scenario: Новый гейт учтён
- **WHEN** в продукт добавлен новый гейт
- **THEN** он объявляет свою применимость без системы и учитывается режимом
