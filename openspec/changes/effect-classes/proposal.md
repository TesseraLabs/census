## Why

Ось «курируемый грант / сырой примитив / способный к эскалации» в Census уже существует,
но только как предупреждения (`RawPrimitiveAlongsidePermissions`, `InlineSudoUnlabeled`),
которые оператор может проматывать. Для профилей безопасности (полный профиль по умолчанию,
ослабление только явным подписанным решением) и для будущих делегаций источникам деклараций
(manifest-fragments) нужна та же ось, но как **вычисляемая классификация с fail-closed
гейтом**: декларация вправе запретить целый класс эффектов, и запрет останавливает apply до
первой мутации, а не пишет строку в лог.

## What Changes

- Вводится шкала классов эффектов: `curated` → `raw` → `escalation`; четвёртый класс
  `unbounded` (произвольное содержимое) существует только как имя запрещённого — ни один
  объект декларации не может его получить, домены с неограниченным содержимым в Census
  структурно не допускаются.
- Класс объекта **вычисляется** из его природы, а не декларируется автором: грант из
  каталога (есть risk-метка и привязка к мерам) → `curated`; перечислимые примитивы без
  каталожной метки (`groups`, `sudo_role`, `limits`, не-исполняемые файловые гранты) →
  `raw`; inline `payload.sudo` и файловые гранты с исполняемым содержимым → `escalation`.
- Декларация получает секцию политики `[policy]` с `max_effect_class`: объект класса выше
  разрешённого — отказ plan/apply **до любых мутаций и до снапшота**, с перечнем
  нарушителей (объект, роль, класс, источник).
- Отсутствие `[policy]` сохраняет сегодняшнее поведение (предупреждения) — совместимость
  не ломается; политика — opt-in.
- `census plan`/`apply`-отчёты аннотируют каждый объект его классом; JSON-контракт
  расширяется полем `effect_class` (добавление поля, не ломающее изменение).

## Capabilities

### New Capabilities
- `effect-classes`: шкала классов, правила вычисления класса для каждого типа объекта,
  политика `max_effect_class` в декларации, fail-closed гейт и отчётность классов.

### Modified Capabilities
- `catalog-resolution`: resolve аннотирует каждый resolved-объект вычисленным классом
  эффекта (раньше — только предупреждения по двум частным случаям).
- `provisioning-apply`: перед мутациями добавляется гейт политики классов (наряду с
  существующими гейтами доверия и anti-lockout).

## Impact

- Код: `src/model.rs` (классификация при resolve), `src/declaration.rs` (секция
  `[policy]`, строгий парсинг), `src/plan.rs`/`src/apply.rs` (гейт, отчёт), JSON-вывод
  plan.
- Контракты: golden-тесты CLI/TOML расширяются (новая секция и новое поле — аддитивно).
- Зависимости: нет новых crate.
- Связанные change'и: `manifest-fragments` (скоуп делегации задаётся в терминах классов)
  и `enumerable-domains` (каждый новый домен обязан объявить классы своих объектов)
  зависят от этой шкалы.
