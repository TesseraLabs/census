# effect-classes Specification (delta: effect-classes)

## ADDED Requirements

### Requirement: Шкала классов эффектов

Census ДОЛЖЕН (MUST) присваивать каждому объявленному объекту ровно один класс эффекта из
упорядоченной шкалы `curated` < `raw` < `escalation`. Класс `unbounded` ДОЛЖЕН (MUST)
существовать как имя запрещённого класса и НЕ ДОЛЖЕН (MUST NOT) присваиваться ни одному
объекту: объекты с неограниченным эффектом в модель Census не входят. Класс ДОЛЖЕН (MUST)
вычисляться из природы объекта и НЕ ДОЛЖЕН (MUST NOT) браться из поля, задаваемого автором
декларации.

#### Scenario: Грант из каталога
- **WHEN** роль объявляет разрешение, разрешаемое каталогом (есть risk-метка)
- **THEN** объектам этого разрешения присваивается класс `curated`

#### Scenario: Сырой перечислимый примитив
- **WHEN** роль объявляет `groups`, `sudo_role`, `limits` или не-исполняемый файловый грант
- **THEN** объекту присваивается класс `raw`

#### Scenario: Способный к эскалации объект
- **WHEN** роль объявляет inline `payload.sudo` либо файловый грант на исполняемое
  содержимое
- **THEN** объекту присваивается класс `escalation`

#### Scenario: Класс не задаётся автором
- **WHEN** декларация содержит попытку задать класс эффекта объекта полем
- **THEN** строгий парсер отвергает декларацию как содержащую неизвестное поле

### Requirement: Политика максимального класса

Декларация ДОЛЖНА (MUST) поддерживать необязательную секцию `[policy]` с ключом
`max_effect_class` со значением из шкалы. При наличии политики Census ДОЛЖЕН (MUST)
отказывать `plan` и `apply`, если хотя бы один объект имеет класс выше разрешённого.
Отказ ДОЛЖЕН (MUST) происходить до любых мутаций и до снятия снапшота и ДОЛЖЕН (MUST)
перечислять нарушителей с указанием роли, объекта, его класса и разрешённого максимума.
При отсутствии секции `[policy]` ограничение НЕ ДОЛЖНО (MUST NOT) применяться.

#### Scenario: Объект превышает разрешённый класс
- **WHEN** политика задаёт `max_effect_class = "raw"`, а роль объявляет inline sudo
- **THEN** plan и apply отказывают до мутаций и до снапшота, перечисляя нарушителей

#### Scenario: Все объекты в пределах политики
- **WHEN** политика задаёт `max_effect_class = "raw"`, а объявлены только курируемые
  разрешения и группы
- **THEN** гейт пропускает, обработка продолжается штатно

#### Scenario: Политика не задана
- **WHEN** декларация не содержит секции `[policy]`
- **THEN** гейт не применяется, поведение совпадает с поведением до этого изменения

#### Scenario: План не показывается при нарушении
- **WHEN** политика нарушена и запрошен `census plan`
- **THEN** команда отказывает, а не печатает план с предупреждением

### Requirement: Консервативная классификация при неоднозначности

Census ДОЛЖЕН (MUST) присваивать объекту более высокий из возможных классов, когда
признак, определяющий класс — в частности исполняемость целевого содержимого файлового
гранта, — не может быть установлен достоверно. Понижение класса при неоднозначности НЕ
ДОПУСКАЕТСЯ (MUST NOT).

#### Scenario: Неопределимая исполняемость
- **WHEN** файловый грант указывает на цель, чью исполняемость установить не удалось
- **THEN** объекту присваивается `escalation`, а не `raw`

### Requirement: Отчётность класса

`census plan` ДОЛЖЕН (MUST) сопровождать каждый объект его классом эффекта в
человекочитаемом выводе и полем `effect_class` в JSON-выводе. Добавление поля ДОЛЖНО
(MUST) быть аддитивным и НЕ ДОЛЖНО (MUST NOT) менять существующие поля контракта.

#### Scenario: JSON-вывод плана
- **WHEN** запрошен `census plan --format json`
- **THEN** каждый объект плана несёт поле `effect_class` со значением из шкалы

#### Scenario: Существующие потребители контракта
- **WHEN** потребитель читает поля JSON-плана, существовавшие до изменения
- **THEN** их имена, типы и значения не изменились
